# NT2 UX improvements — 10 November 2026

## Analysis and scope
The existing Next.js 16 / React 19 app already has Supabase identity and PostgreSQL persistence, exercise drafts and results, adaptive evidence, a multilingual translation cache, coach character preferences, speech controls, and a short language check. This change extends those components. No database migration, provider switch, dependency, or role change is required.

## Changes
- Dashboard: one prominent recommendation with level, estimated minutes and direct exercise launch. Other dashboard sections remain; their exercise links use secondary styling.
- Recommendations: use the existing rotating catalogue and saved independent scored attempts. Two distinct low-scoring exercises are required before prioritising a subject. Assisted/duplicate attempts do not establish difficulty. Prefer fresh exercises over the latest attempt. No AI-based error labels are invented.
- Coach: server-side level instructions use the saved student profile, including teacher overrides. A1 responses are limited to 2–3 short sentences; A2 gets short explanations, one new word at a time. One question and at most one real correction, with hints rather than completed answers.
- Exercise results: “Wat ging goed?”, “Wat kan beter?”, “Wat kan ik nu oefenen?”, at most three highlighted improvements, original and correct answers and existing explanations. Writing remains explicitly self-reviewed. Existing retry and saved progress are preserved.
- Conversation reflection: same three headings, using only actual learner messages; explicitly says the selected sentence has not been assessed. No fabricated corrected sentence or mastery judgment.
- First visit: coach introduces itself, offers language selection, then four steps with arrows/highlights. Supports keyboard navigation, skip, back, replay, and direct start. Existing translation pipeline is reused and tour texts take queue priority. Dutch/English/Arabic tour copy is bundled; other languages depend on the existing AI translation service and cache. Failed translation offers retry/skip and does not silently advance in Dutch.
- Tour dismissal is stored per account in the current browser only. Clearing browser storage or moving to another device can show it again. No sensitive learner text is added to storage.
- Simpler primary navigation, level check and exercise instructions; focus outlines, skip link, long-message wrapping, reduced-motion handling, and mobile tour layout.

## Verification
- Production Next.js build and TypeScript checks pass.
- 64 automated tests pass on the project's required Node 24, including recommendation selection, insufficient evidence, assisted work, duplicate attempts and level-specific coaching instructions.
- Browser check with isolated local fixtures: automatic intro, Arabic RTL tour, four steps, direct exercise launch, input, result headings, retry, closing and replay.
- Mobile viewport 390×844: no document horizontal overflow, legible tour with the target visible above it. Existing desktop/tablet layout also inspected.
- Fixtures were removed from the application before production build. No production student results were created during these checks.

## Verification limits and follow-up
Live Supabase writes, new account creation, email delivery, live AI answer quality and real microphone input were not verified in this change: local secrets/authenticated test access were unavailable. This is not a full WCAG certification or a complete linguistic review of every lesson and language. Have the NT2 teacher review A1/A2 copy and Arabic translations during the planned user test; check the languages participants will actually use before the session. Watch provider quotas during simultaneous classroom use.

Future: optional server-persisted tour completion, finer error categories only when supported by validated feedback, broader authored offline tutorial translations, and measured contrast/screen-reader testing across all custom themes.
